# Paper 플러그인 구현 계획

## 보호 서버 접근

- 보호 서버마다 중앙 정책의 서버 식별자를 설정합니다.
- Paper의 Velocity modern forwarding과 백엔드 네트워크 접근 제한을 필수 운영 조건으로 둡니다. 플러그인만으로 프록시 우회를 방지한다고 간주하지 않습니다.
- 접속한 UUID와 서버 식별자로 최신 접근 상태를 확인합니다. 유효한 허용 상태가 확인되기 전에 플레이어가 서버에서 활동하지 못하게 합니다.
- API 확인은 서버 메인 스레드를 막지 않도록 수행하고 결과 적용만 적절한 스레드에서 처리합니다.
- 명시적 거부·정지·만료된 정책은 허용으로 해석하지 않습니다.
- 회수 시 Velocity의 대기 서버 이동을 요청할 수 있으나, 요청 실패가 미허용 사용자 체류를 허용하지 않도록 연결 종료 경로도 둡니다.
- API 장애 때의 기존 접속자 유예 시간은 Velocity 및 중앙 정책과 동일한 계약을 따릅니다.

## prefix·표시 정책

- 중앙 프로필은 표시용 prefix와 접근 정책을 구분해 제공합니다.
- LuckPerms 연동은 Passport가 관리하는 그룹·메타데이터 범위만 수정합니다. 운영자가 별도로 부여한 권한과 기존 그룹을 일괄 제거하지 않습니다.
- Paper 채팅 renderer와 Adventure 컴포넌트를 사용합니다. 사용자 입력을 허용되지 않은 서식·클릭 이벤트로 해석하지 않습니다.
- 채팅·탭 목록·머리 위 이름 중 첫 버전에서 지원하는 위치를 명시하고, 기존 표시 플러그인과 겹치는 기능은 설정으로 선택하도록 합니다.
- prefix 변경은 회원 상태 변경의 표시 결과이며 그 자체가 권한 증명이 아닙니다.
- 학교 학번이나 실명을 prefix로 자동 공개하지 않습니다. 표시할 항목은 운영 정책으로 별도 결정합니다.
- Discord 숫자 ID는 소유권 미확인 사용자 입력값이므로 표시 권한이나 접속 권한 결정에 사용하지 않습니다.

## 구현 완료 조건

- 프록시가 정상 판정한 사용자만 해당 서버에서 활동할 수 있습니다.
- 네트워크·forwarding 설정을 포함한 실제 배치에서 직접 접속이 차단됩니다.
- 정지나 접근 회수 후 해당 서버의 활동이 계속되지 않습니다.
- Passport 표시 정보를 갱신해도 기존 LuckPerms 권한을 훼손하지 않습니다.
- API 장애와 플러그인 재시작에서 접근 상태와 표시 상태를 구분해 처리합니다.
- 다른 채팅·탭 표시 플러그인과의 공존 설정을 실제 서버에서 확인합니다.
